01

What makes the database different

Several retrieval engines. The same Postgres rows.

The advantage is not a magical search mode. It is that relational truth, text indexes, embeddings, and graph projections can share stable row IDs and transactional source data without exporting Tony's brain into separate databases that drift apart.

Select a retrieval rail

Authoritative center PostgreSQL rows and IDs Claims, evidence, time, permissions, and ratification stay here.

One database removes synchronization work. It does not remove modeling, indexing, permissions, query planning, operational maintenance, or scale testing.

What "a lot of data" means in practice

Polygres can hold operational rows, graph relationships, search text, and vectors in one project. It is not unlimited. Current managed tiers publish storage, graph-memory, connection, depth, and result limits. The product-specific question is whether supported personal knowledge remains easy to find as fan-out, ambiguity, evidence size, and tenant filtering grow.

Live system audit

Are we set up to use Polygres?

Partly. Fuzzy Brain chose the right foundation, but the application still uses Polygres mostly as ordinary hosted PostgreSQL.

We are not boxed in. The raw data already lives in the correct authoritative system. The missing work is additive: richer relational shapes, rebuildable search projections, retrieval configurations, and a controller that knows how to use them.

03

The scalable knowledge shape

Keep raw life whole. Make knowledge addressable.

The false choice is one giant fact sentence versus thousands of contextless graph atoms. Preserve the original episode, then add separately governed evidence, claims, meanings, and search cues.

Evidence plane

What actually happened or was said

  • Immutable raw episodes
  • Exact source spans
  • External records and locators
  • Capture time and event time

Knowledge plane

What the brain may state as knowledge

  • Entities and aliases
  • Typed claims
  • Validity and supersession
  • Authority and currentness

Meaning plane

What Tony decided the connection means

  • Human-authored why
  • Themes and tensions
  • Beliefs and revisions
  • No automatic promotion

Index plane

What helps machines find an entry point

  • Search projections
  • TSVector and fuzzy text
  • Embeddings and aliases
  • Rebuildable machine cues
Tony --partner_of [human label: girlfriend]--> Doan Doan --lives_in--> Safford Safford --located_in--> Arizona

Tony's example was right: girlfriend is the description or role on the edge between Tony and Doan, not a separate person node. A stable predicate such as partner_of can carry the personal label girlfriend and its aliases.

The sentence "Tony's girlfriend lives in Safford" should exist as a generated search projection. It is useful duplication for retrieval, but it is not a second source of truth.

04

The system to create

Evidence-Guided Graph Recall

Do not encode "if the girlfriend's city is missing, check Uber Eats." Encode a reusable transition: a required value is missing, an authorized evidence source exists, so inspect that source within a budget.

  1. InterpretIdentify the information need.
  2. AnchorSearch exact, lexical, semantic, and alias cues.
  3. ResolveMap mentions to stable entities.
  4. ExpandTraverse allowed typed relations.
  5. EvaluateInspect evidence, time, and authority.
  6. ActChoose the next authorized operator.
  7. StopAnswer, abstain, or propose repair.

Reusable operator library

exact_lookup search_text search_semantic resolve_entity expand_graph find_path read_evidence compare_claims call_authorized_source propose_repair stop

Controller working state

Every recall keeps the question, resolved anchors, open information needs, candidate paths, collected evidence, conflicts, available permissions, and remaining budget. Each result changes that state and therefore changes the next action.

Use strict ceilings for hops, candidates, tool calls, elapsed time, and evidence size. This creates general search behavior without unbounded brute force.

New edge cases should improve an operator, relation definition, ranking signal, or failure classifier. They should not become a growing list of personal if-statements.

05

Tell me, find out why, then fix it

Every failed answer becomes a named state and a verified repair.

The companion should tell Tony what happened immediately, diagnose the reason, perform only an authorized repair, and rerun the original question. Machine indexes may be repaired automatically. Human knowledge and meaning still require Tony's approval.

    07

    The isolated test

    Compare knowledge shapes before changing the real brain.

    The runnable experiment lives only in brain_dev.recall_lab_* tables. It uses the same Polygres project for relational data, TSVector, pgvector, HNSW, and hybrid query plumbing. It does not modify public nodes, edges, talks, or the live pgGraph registration.

    Lane A / Sentence only

    Fast direct recall

    Measures easy text retrieval and how quickly updates, evidence, and repeated wording become tangled.

    Lane B / Typed graph

    Composable paths

    Measures deterministic multi-hop traversal when the starting entity is already known.

    Lane C / Hybrid

    Find, traverse, prove

    Uses text or vector cues for anchors, typed claims for paths, and evidence for the answer gate.

    Important Polygres limit discovered

    The live pgGraph extension is 0.1.7, where graph registration is database-global. A separate schema does not isolate a graph build. The lab therefore uses recursive claim traversal now. The companion disposable pgGraph 0.1.8 probe verified a separate named graph with direct partner_of, lives_in, and located_in hops, plus hydrated relationship reasons and evidence. The managed project can use that shape after its extension reaches 0.1.8.

    Scale only after correctness survives

    1. 100Prove supported answers, identity resolution, evidence paths, and every epistemic state.
    2. 1,000Introduce aliases, duplicate names, repetitive facts, and ambiguous anchors.
    3. 10,000Measure index behavior, bounded traversal, fan-out, and false paths.
    4. 100,000Measure p50 and p95 latency, storage, HNSW build time, graph memory, and context size.
    5. 1,000,000Only after the earlier tier stays faithful; test tenant filtering and maintenance behavior.

    The headline metric is supported personalized usefulness. Retrieval recall and latency explain failures, but they are not the product's definition of success.

    08

    Technical sectors and build order

    Learn and prove the contract before optimizing the engine.

    1. P0Knowledge representation and epistemology. Entities, claims, evidence, meanings, authority, time, and revision.
    2. P0Evaluation science. Supported personalization, blind preference, missing-state accuracy, and false-path rate.
    3. P0Isolated Polygres experiment. Compare sentence, graph, and hybrid shapes without touching public data.
    4. P1Information extraction and entity resolution. Raw span to candidate claim, with no silent promotion to truth.
    5. P1Information retrieval. Exact, TSVector, fuzzy, vector, scalar filtering, and candidate fusion.
    6. P1Graph systems and temporal queries. Typed traversal, path budgets, currentness, and evidence hydration.
    7. P2Agent planning and tool orchestration. Generic operators, authorized source calls, stop conditions, and repair.
    8. P2Observability and security. Search traces, audits, RLS, brain isolation, and per-agent scopes.
    9. P3Universal access and the companion harness. Stable API or MCP packets that preserve evidence and epistemic state.
    10. P4Companion identity and training. Build after external memory and the harness prove where model behavior is still insufficient.
    09

    Human decisions the database cannot make

    Tony still defines the authority boundary.

    1. Which source-backed facts may be accepted automatically, and which always require Tony's ratification?
    2. Which external sources may the recall controller inspect without asking every time?
    3. What counts as enough evidence to stop and personalize an answer?
    4. May the system automatically repair machine aliases and indexes while only proposing human knowledge changes?
    5. Which parts of Tony's raw evidence may each model or companion read?
